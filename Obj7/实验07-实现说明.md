## 三、数据库设计

数据库文件：**项目内新建的 `db` 文件夹**下的 `jspchatroom/db/chatroom.mv.db`
（H2 File Mode；目录不存在时启动阶段由 `DBUtil` 自动创建，库文件由 H2 自动创建）。
该目录里还有一个 `README.txt` 说明用途；`db/*.mv.db` 已加入 `.gitignore`，数据文件不会误提交。

### users（用户表）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `INT GENERATED BY DEFAULT AS IDENTITY` | 用户编号，主键自增 |
| `username` | `VARCHAR(50) NOT NULL` | 用户名，`UNIQUE` 约束 `uk_users_username` |
| `password` | `VARCHAR(200) NOT NULL` | 密码摘要，格式 `盐$SHA-256摘要` |
| `created_at` | `TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP` | 注册时间 |
| `last_login_at` | `TIMESTAMP` | 最近登录时间（首次登录前为 NULL） |
| `online` | `BOOLEAN NOT NULL DEFAULT FALSE` | 在线状态 |

### messages（消息表）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `INT GENERATED BY DEFAULT AS IDENTITY` | 消息编号，主键自增 |
| `user_id` | `INT NOT NULL` | 发送者编号，外键 `fk_messages_user → users(id)`，级联删除 |
| `content` | `VARCHAR(500) NOT NULL` | 消息内容（页面同样限制 500 字） |
| `created_at` | `TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP` | 发送时间 |

另建索引 `idx_messages_created_at ON messages(created_at)`，让“取最近 N 条”更快。

实际建表语句见 `DBInitListener` 中的 `DDL_USERS` / `DDL_MESSAGES`。

## 四、关键实现说明

### 4.1 依赖与连接配置

`pom.xml` 按实验文档引入：

```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <version>2.2.224</version>
    <scope>runtime</scope>
</dependency>
```

同一份 `h2-2.2.224.jar` 也放进了 `src/main/webapp/WEB-INF/lib`（与第 06 次实验处理 JSTL 的方式一致），
这样 IntelliJ IDEA 的 exploded-war 工件在部署时也会带上驱动，不会出现 `ClassNotFoundException: org.h2.Driver`。

连接参数集中在 `src/main/resources/db.properties`：

```properties
jdbc.url=jdbc:h2:file:C:/Users/zhang/Desktop/上课/Jakarta/EE/Obj7/jspchatroom/db/chatroom
jdbc.user=sa
jdbc.password=
```

这里用**绝对路径**指向项目内新建的 `db` 文件夹（`jspchatroom/db/`）。
之所以不写相对路径，是因为 Tomcat 的“当前工作目录”通常是 `<Tomcat>/bin`，
`./db` 会跑到 Tomcat 目录里而不是项目里；写成绝对路径最直观、可控。

`DBUtil` 启动时会解析这个 URL：

```java
databaseFile = Paths.get(path).toAbsolutePath().normalize();   // 转成绝对路径
Files.createDirectories(databaseFile.getParent());             // 项目内没有 db 目录就自动建
System.out.println("[DBUtil] 数据库目录: " + dir);              // 控制台打印实际位置
System.out.println("[DBUtil] 数据库文件: " + databaseFile);
```

因此：
* 数据库文件**不在** Tomcat 的 `webapps`、也不在 IDEA 的 `target` / `out` 里，
  重新部署、清理构建都不会丢数据 —— 这是“重启后仍有历史记录”的前提；
* 整个 `db` 目录被误删也没关系，下次启动会自动重建（已实测）。

> 换电脑/换项目目录时，只需改 `db.properties` 里那一行路径；
> 想临时换库：启动参数加 `-Dchatroom.jdbc.url=jdbc:h2:file:D:/mydb/chat` 即可，无需改代码。

### 4.3 `DBUtil`：JDBC 编程流程的集中体现

```java
Class.forName("org.h2.Driver");                    // 1. 加载驱动
Connection c = DriverManager.getConnection(url, user, pwd);  // 2. 建立连接
PreparedStatement ps = c.prepareStatement(sql);    // 3. 预编译 SQL
ps.setString(1, value);                            // 4. 设置参数（防注入）
ResultSet rs = ps.executeQuery();                  // 5. 执行并处理结果
// try-with-resources 自动关闭 rs / ps / c          // 6. 释放资源
```

`getConnection()` 每次调用返回新连接，用完即关；`close(AutoCloseable...)` 提供静默关闭。

### 4.4 DAO 层

* `UserDao`
  * `findByUsername(String)` — 登录校验、注册查重
  * `existsByUsername(String)` — 注册重名检查
  * `create(String, String)` — 注册入库（`RETURN_GENERATED_KEYS` 取回自增编号）
  * `markLogin(int)` — 更新 `last_login_at`、`online = TRUE`
  * `setOnline(int, boolean)` / `resetAllOnline()` — 在线状态维护
  * `findOnlineUsers()`、`countUsers()`
* `MessageDao`
  * `insert(int userId, String content)` — 保存一条聊天记录
  * `findRecent(int limit)` — `JOIN users` 取最近 `limit` 条（`ORDER BY created_at DESC LIMIT ?`），
    再反转为由旧到新，页面显示更符合聊天习惯
  * `countMessages()` — 历史消息总数

所有 SQL 都用 `?` 占位符，杜绝 SQL 注入。

### 4.5 注册与登录（`register.jsp` / `login.jsp`）

登录核心逻辑：

```java
User found = userDao.findByUsername(username);
if (found == null || !PasswordUtil.matches(password, found.getPassword())) {
    request.setAttribute("error", "error.login.failed");   // 不区分“用户不存在/密码错”
} else {
    userDao.markLogin(found.getId());        // 更新最近登录时间 + 在线
    HttpSession s = request.getSession(true);
    s.setAttribute("currentUser", found);    // 登录状态来自数据库校验结果
    response.sendRedirect(ctx + "/chat.jsp"); // PRG
    return;
}
```

错误提示用 `<c:if test="${not empty error}"><fmt:message key="${error}"/></c:if>` 显示，
错误信息本身是国际化 key（`error.login.failed` 等），中英文各一份。

注册成功后用 `response.sendRedirect("login.jsp?registered=1")` 回到登录页并提示“注册成功”，
避免刷新导致重复注册。

### 4.6 消息持久化与 JSTL 展示（`chat.jsp`）

```java
// 发送（POST）：写入数据库，然后重定向（PRG）
if ("POST".equalsIgnoreCase(request.getMethod())) {
    String msg = (String) request.getAttribute("filteredMsg");  // EncodingFilter 已做敏感词替换
    if (msg == null) msg = request.getParameter("msg");
    ... 校验、截断 500 字 ...
    messageDao.insert(currentUser.getId(), msg);
    response.sendRedirect(ctx + "/chat.jsp" + langQuery);
    return;
}
// 展示（GET）：从数据库读取最近的 N 条（N 取自 web.xml 的 maxMessageCount）
List<Message> messages = messageDao.findRecent(maxMessageCount);
request.setAttribute("messages", messages);
```

页面用 JSTL 遍历：

```jsp
<c:forEach var="m" items="${messages}">
    <li>
        <span class="meta">[<fmt:formatDate value="${m.createdAt}" pattern="MM-dd HH:mm"/>]</span>
        <b><c:out value="${m.username}"/></b>:
        <c:out value="${m.content}"/>
    </li>
</c:forEach>
```

时间格式化交给 `fmt:formatDate`，输出转义交给 `c:out`（第 06 次实验用
`escapeXml="false"` 直接输出原始内容，存在 XSS 风险，本次已修正）。

底部还有一行提示「当前显示最近 {0} 条消息（数据库中共 {1} 条，最多加载 {2} 条）」，
直观体现“只加载最近若干条”的设计。

### 4.7 在线状态与会话

| 时机 | 处理 |
| --- | --- |
| 登录成功 | `users.online = TRUE`，`last_login_at = 当前时间` |
| 点击退出 | `logout.jsp` 置 `online = FALSE` → `session.invalidate()` → 回登录页 |
| 会话超时/浏览器关闭 | `SessionLifecycleListener#sessionDestroyed` 置 `online = FALSE` |
| 应用启动 | `DBInitListener` 把所有用户 `online` 清为 FALSE（重启后没有在线会话） |

`AuthFilter`（映射 `/chat.jsp`、`/logout.jsp`）判断 `session.currentUser`，未登录直接重定向登录页，
因此不登录无法通过地址栏直接进入聊天室。

### 4.8 密码安全性（对应“思考与扩展 2”）

`PasswordUtil` 使用 **随机盐 + SHA-256**：

```
数据库 password 字段 = 盐(32位十六进制) + "$" + SHA-256(盐 + 明文)(十六进制)
```

* 注册：`userDao.create(username, PasswordUtil.hash(password))`
* 登录：`PasswordUtil.matches(明文, 库中的值)` —— 用同样的盐重算摘要后
  以 `MessageDigest.isEqual` 做定长比较。
* 兼容性：库中的值若不含 `$`，按明文比较（兼容教学早期数据）。

真实项目更推荐 BCrypt / Argon2（自带慢哈希与自适应成本），本实现用 JDK 自带 API，
不引入额外依赖即可演示“加盐摘要”的完整流程。

## 五、运行步骤（IDEA + Tomcat）

1. **导入依赖**：打开 `jspchatroom/pom.xml`，等待 Maven 重新导入（会下载 `h2-2.2.224`）。
   若离线环境，`WEB-INF/lib` 里已经有 `h2-2.2.224.jar`，可直接运行。
2. **确认 JDK 17+**：Jakarta EE 11 / Servlet 6.1 需要 Java 17 以上（本机 JDK 21 可用）。
3. **确认 Tomcat 11**：`web.xml` 为 6.1 版本，需要 Tomcat 11（本机已有
   `D:\Software\Tomcat\apache-tomcat-11.0.25`）。
4. **Rebuild Project**（`Build → Rebuild Project`），让新的 class、JSP 和 `WEB-INF/lib/h2-2.2.224.jar`
   进入 exploded-war 工件。
5. 启动 Tomcat，浏览器访问 `http://localhost:8080/jspchatroom/`（默认欢迎页是 `login.jsp`）。
6. 观察控制台：应出现 `🔄 初始化数据库...` 与 `✅ 数据库初始化完成！`。
7. 注册 → 登录 → 发消息 → **重启 Tomcat** → 重新登录，历史消息仍在。

> 数据库文件位置：**项目内** `jspchatroom\db\chatroom.mv.db`（登录页底部也会显示该路径）。
> 想清空重来：停掉 Tomcat，删除 `db\chatroom.mv.db` 即可（下次启动会重新建库建表）。

## 七、思考与扩展

### 1. JSP 与 Servlet 的职责

* **写在 JSP 里**：`<% ... %>` 直接连库、校验、跳转。优点是文件少、上手快，适合课堂演示；
  缺点是 JSP 同时承担“接收请求—业务判断—访问数据库—输出 HTML”，页面臃肿，
  无法单元测试，改一行 HTML 也要动业务代码，多人协作时冲突频繁。
* **写在 Servlet 里**：Servlet 只做「取参数 → 调用业务/DAO → 把结果放进 request → 转发给 JSP」，
  JSP 只做「用 EL/JSTL 把数据渲染成 HTML」。业务逻辑可以独立测试、复用（同一份逻辑可同时给网页和接口用），
  页面改版不影响业务代码。
* **功能越复杂，Servlet（分层）方式越容易维护**。本次改造已经把“SQL”这部分抽到了
  `UserDao` / `MessageDao`，JSP 只调用方法、不再拼 SQL，这正是向 MVC 过渡的第一步。
* **如何让 JSP 只负责显示**：
  1. 控制器（Servlet）接收请求、校验参数、调用 Service/DAO；
  2. 把模型放进 `request.setAttribute(...)`；
  3. `request.getRequestDispatcher("/chat.jsp").forward(...)`；
  4. JSP 里只保留 `${...}`、`<c:forEach>`、`<fmt:message>`，不再出现 `<% %>` 与 `import java.sql.*`。
  下一步可以按这个思路把 `login/register/chat` 三个页面拆成 `LoginServlet`、`RegisterServlet`、
  `ChatServlet` + 纯视图 JSP，形成标准的 MVC + 分层架构。

### 2. 密码安全性

本实现已落地（见 4.8）：注册时用**随机盐 + SHA-256** 生成 `盐$摘要` 存库，登录时用同样的盐重算再定长比较。
要点：

1. **绝不明文入库**：数据库泄露时摘要无法直接反推密码；
2. **必须加盐**：同一密码在不同用户处得到不同摘要，防止彩虹表与“批量撞库”；
3. **比较用定长比较**（`MessageDigest.isEqual`），避免通过比较耗时做侧信道攻击；
4. **升级方向**：SHA-256 是“快哈希”，可被 GPU 高速暴力破解，真实项目用 BCrypt / Argon2 / scrypt
   （自带成本因子，每次校验故意慢一点）；另外还应加登录失败次数限制、HTTPS 传输、密码强度策略。

### 3. 数据展示与分页

* 本实现通过 `web.xml` 的 `maxMessageCount=50` 限制一次读取的条数，SQL 为
  `ORDER BY created_at DESC, id DESC LIMIT ?`，只取最近 50 条并在 Java 中反转为正序；
  页面底部会显示「数据库中共 N 条，最多加载 M 条」。
* 如果要**分页**：把 `LIMIT ?` 扩展为 `LIMIT ? OFFSET ?`（H2 还支持 `FETCH FIRST n ROWS ONLY`），
  页码 `page` 从请求参数取，`OFFSET = (page-1)*pageSize`；同时用 `COUNT(*)` 算出总页数，
  在页面上渲染「上一页 / 下一页」。
* 如果要**按时间续加载**（聊天室更常见）：记住当前最旧一条的 `id`（或 `created_at`），
  点击「加载更早」时用 `WHERE id < ? ORDER BY id DESC LIMIT ?` 再取一批，
  避免深分页带来的 `OFFSET` 性能问题。
* 另外可加索引（本次已建 `idx_messages_created_at`）、只查询需要的列、把“在线用户”等
  高频查询做短时间缓存，进一步降低数据库压力。

## 八、常见问题排查

| 现象 | 原因与解决 |
| --- | --- |
| 启动报 `ClassNotFoundException: org.h2.Driver` | H2 驱动没进 `WEB-INF/lib`。确认 `src/main/webapp/WEB-INF/lib/h2-2.2.224.jar` 存在并重新 Build；或 Maven 重新导入 pom |
| 控制台出现 `❌ 数据库初始化失败` | 看随后的异常堆栈：SQL 语法、文件被占用、磁盘权限等。常见是数据库文件被另一个进程（如 H2 Console）锁住 |
| 页面 500，日志 `The database is read only` | 数据库文件所在目录不可写（如项目被放在只读盘、或被杀毒软件锁住），或已有别的进程以只读方式打开；确认 `jspchatroom\db` 可写即可 |
| 中文乱码 | `EncodingFilter` 与各 JSP 的 `pageEncoding`/`contentType` 已统一 UTF-8；若 IDEA 控制台乱码，设置 `-Dfile.encoding=UTF-8` |
| 改了代码但页面没变化 | IDEA 需要 `Build → Rebuild Project` 重新生成 exploded-war；JSP 可直接热更新，Java 类需要重启 |
| 想重置数据 | 停 Tomcat，删除 `jspchatroom\db\chatroom.mv.db`（或整个 `db` 目录），重启即重新建库建表 |
